# Feature registry: what each release changed, what number reads it, and whether it is measured

Owner of this file: the `release-impact` agent (`.claude/agents/release-impact.md`). Rule behind it:
[`docs/measurement-definition-of-done.md`](../measurement-definition-of-done.md). One row per change that users or money
can feel. The panel plan that turns these rows into sections: [`RELEASE-IMPACT-PANEL-PLAN.md`](RELEASE-IMPACT-PANEL-PLAN.md).

Filled 2026-10-19 by the release-impact agent, read-only, from: the decision files 0162-0226 (0164-0211 read from
`gitlab/main`, they are not on this branch), the release scripts `kaam/ops-scripts/android-15{0,1,2,3}-*-release.sh`,
the app's git history between the release heads below (`git log --no-merges`), and the research reports in
`kaam/research/` (each number below names its source). Nothing was built or deployed to fill it.

## How to read a row

- **The ONE number** is the number the owner reads first, with its denominator. "Per device" always means one row per
  `app_instance_id`, release builds, our own phones removed (`internal-test-accounts-and-devices`), Android and iOS never
  mixed.
- **Expectation.** `declared` = written in the decision before release (quoted). `reconstructed` = not written before
  release; this is what it should have said, written after the fact, so it **cannot** be used to claim a win. It is
  there so the section has a line to compare against from now on.
- **Guardrails** use the four families of the agent file: **T** trust (crash, ANR, `error_shown`, sync, retention,
  rating), **M** money (ad revenue per user-day by format, paywall views, Continue, net revenue per viewer), **A**
  activation (G1 24 h / 7 d per new install), **S** speed (cold start, splash pass-through, ad wait). Every row carries
  all four; a row lists only the ones the change can plausibly touch, the rest read "standard set" in the plan.
- **DoD 1-7** = the seven things of the definition of done, in order: 1 question written in the decision, 2 events,
  3 backend query + endpoint + panel section, 4 synthetic data with a known answer, 5 data-travel test, 6 Health Centre
  silence check, 7 n shown / "not enough data" below the threshold. `Y` yes, `P` partly, `N` no, `-` not applicable.
- **Verdict** is the agent's recommendation with its date: KEEP / ITERATE / ROLL BACK / WAIT, or `not read`.
  "associated" means not randomised: it cannot say "caused".
